# Languages

Zona Dron ships in **Spanish and English**, switchable in Settings → Language
(system / Español / English). This note explains how that works, what
deliberately stays in Spanish, and how to add a string or a third language.

## What is translated, and what is not

**Translated:** everything the app writes itself — screens, buttons, empty
states, accessibility labels, the verdict sentences, the ED-318 code labels, the
regulation summary, the drone profiles, dates, times and decimal separators, and
the place names that come back from Nominatim (the app asks for them in the
interface language).

**Not translated, on purpose:**

| What | Why |
|---|---|
| ENAIRE zone names, official text, conditions, contacts | Published in Spanish only. Machine-translating a legal restriction and then acting on it is exactly the wrong move for an app whose whole point is not being wrong about restrictions. |
| NOTAMs | Raw aeronautical text with ICAO abbreviations. Not ours to rewrite. |
| Protected natural area names | Official names of parks and reserves, in Spanish and the co-official languages of each region. |
| The authorization request e-mail (`src/logic/request.ts`) | It goes to Spanish zone managers and AESA. It stays in Spanish whatever the interface language is — this is a case where the correct behaviour is *not* to translate. The zone card says so when the app is in English. |
| Links to official documents | The regulation, the AESA guidance and the ENAIRE service docs are Spanish PDFs. The rules screen says so in English. |

So an English session is bilingual on screen: English chrome around Spanish
official text. That is normal for aviation tools, and the app states it rather
than hiding it.

## How it works

```text
src/i18n/
  index.ts     t(), setLocale(), dateLocale(), decimal(), acceptLanguage()
  es.ts        the reference dictionary
  en.ts        the same keys in English, checked by the compiler
src/logic/
  rules.es.ts  rules.en.ts    the regulation summary, one file per language
  drone.es.ts  drone.en.ts    the drone profiles
```

- `t('key')` for fixed text, `t('key', arg…)` when the string takes data. Values
  in the dictionary are either strings or functions, so plurals and word order
  live in each language rather than being stitched together at the call site.
- **The current language is module state, not React state.** The decision engine
  (`verdict.ts`), the share text, the sun maths and the offline evaluation all
  produce text and none of them are components. `SettingsProvider` calls
  `setLocale()` during render, before anything else draws.
- **Changing the language remounts the navigation tree** (`app/_layout.tsx`).
  A verdict already computed carries its text inside it, so without a remount
  the screen would keep sentences in the previous language until the next query.
- `en.ts` is typed as `Messages`, derived from `typeof es`: a missing key, a
  typo, or a function with the wrong arguments is a compile error.
  `tests/i18n.test.ts` adds what the compiler cannot see — that no string was
  left untranslated by accident, and that both languages expose the same drone
  profiles and rule sections.

## Adding a string

1. Add the key to `src/i18n/es.ts`, in the section for that screen.
2. Add the same key to `src/i18n/en.ts`. The compiler will tell you if you don't.
3. Use `t('your.key')` in the component. Never inline a literal — `npm run
   test:unit` will not catch it, but the next person reading the screen will.

Dates and times go through `dateLocale()`, decimals through `decimal()`.

## Adding a third language

1. Copy `en.ts` to, say, `fr.ts` and translate it; the `Messages` type keeps you
   honest.
2. Copy `rules.en.ts` and `drone.en.ts` the same way.
3. Register the locale in `src/i18n/index.ts` (`Locale`, `LOCALES`, `DICTS`,
   `dateLocale`, `acceptLanguage`, `resolveLocale`) and in
   `src/state/SettingsContext.tsx` (`LANGUAGES`, `languageLabel`,
   `VALID_LANGUAGES`).
4. Add `locales/fr.json` with the native permission strings and register it in
   `app.json`.
5. `npm run typecheck && npm run test:unit`.

The two per-language content files (`rules`, `drone`) are the real work: they
are whole paragraphs of regulation summary, and a bad translation there is worse
than no translation.
